# Antigravityへの委譲ルール（Claude Code向け）

このフォルダの仕組みを使うときのルール。**クラさんではなくClaude Codeが守るもの。**

## 役割分担

| | 担当 | 内容 |
| --- | --- | --- |
| 考える | Claude Code | 設計、作業の分解、指示書の作成、結果のレビュー、git commit |
| 手を動かす | Antigravity（agy） | 指示書どおりの実作業。無料枠で動く |

Claude Codeのトークンは「考える」に使う。ルーチンな実装・大量ファイル処理・定型調査は
指示書に落としてAntigravityに渡す。**逆は禁止**：設計判断をAntigravityに委ねない。

## 委譲する / しない の判断

**委譲してよい**
- 手順が決まっている実装（既存パターンの横展開、テストの追加、リネーム、フォーマット）
- 大量ファイルの機械的な処理
- 定型調査（出典を集めてまとめる）
- 動かして直すループ（テストが通るまで直す、など完了条件が機械的に判定できるもの）

**委譲しない**
- 設計そのもの（何を作るか、どう分けるか）
- クラさんの仕事の中身に関わる判断（案件の方針、価格、表現）
- `AI-Harness\hermes` 配下の稼働中スクリプトの変更
- 秘密情報（APIキー、個人情報、取引先情報）を含む作業
- 完了条件を言葉で定義できない作業 ← **定義できないなら、まだ委譲の段階ではない**

## 手順

1. `templates\` のテンプレートから指示書を作り、`specs\YYYYMMDD-（内容）.md` に保存する
2. 「やらないこと」を必ず埋める。特に **commit/push禁止** は毎回入れる
3. `Invoke-Antigravity.ps1 -SpecPath <指示書> -WorkDir <作業先>` で投げる
4. `runs\<日時>\response.md` と `git diff` を**必ず自分で読む**。agyの報告を鵜呑みにしない
5. 問題なければClaude Codeがcommitする。おかしければ指示書を直して再投入する

## ループで回すとき（Invoke-AntigravityLoop.ps1）

1回投げて終わりではなく、**合格するまで直させる**場合はこちら。
`templates\ループ指示書テンプレート.md` を使う。

```
.\Invoke-AntigravityLoop.ps1 -SpecPath <指示書> -VerifyCommand '<検証コマンド>' -WorkDir <作業先> -MaxAttempts 3
```

守ること:

- **検証コマンドが書けない作業はループに載せない。** 書けないなら、まだ設計が足りていない
- **合否を決めるのは検証コマンドの終了コードだけ。** agyの「できました」を信じない
- **上限を必ず置く。** 既定3回。5回を超える設定にしたくなったら、指示書か検証の方が悪い
- 次の試行に渡すのは**直前の失敗だけ**。全履歴を積み上げない（そのように作ってある）
- 枠切れ（終了コード3）を検知したら、試行を残して即座に止まる

### ループで壊れる4つの型（毎回意識する）

| 型 | どう出るか | 防ぎ方 |
| --- | --- | --- |
| 未検証のまま採用 | 検証が甘く、通っていないものが通ったことになる | 検証コマンドを具体的にする。緩めさせない |
| 理解の負債 | 動くコードは増えたが、クラさんも私も中身を説明できない | `git diff` を必ず読む。読めない量なら指示書を割る |
| 意図の負債 | なぜそうしたかが残らず、後で見直せない | commitメッセージとNotionに「なぜ」を書く |
| 思考の明け渡し | 出てきたものをそのまま受け入れるのが癖になる | 合格しても一度は疑う。**特に下の学習の件** |

### 学習中のコードはループに載せない

案件ナレッジDBに「Hermesのコードをクラさんの学習教材にし、Claude Codeはペアプロ的に
レビュー・提案する」という**確定方針**がある。ここをループで自動化すると、方針そのものが消える。
学習対象として選んだコードは、ループではなくクラさんが書き、私がレビューする。
**効率化していい場所と、してはいけない場所を混ぜない。**

## 失敗したとき

| 終了コード | 意味 | 対応 |
| --- | --- | --- |
| 0 | 成功 | 差分をレビューしてcommit |
| 1 | agyがERROR等 | `runs\<日時>\stderr.txt` を読む。指示書が曖昧なことが多い |
| 2 | 前提不足（agy未導入・指示書なし） | セットアップを確認 |
| 3 | 無料枠切れの疑い | 指示書は `specs\` に残し、枠が戻ってから再投入。急ぐならClaude Codeが自分でやる |

ループの終了コードも同じ意味（0=合格 / 1=上限まで不合格 / 2=前提不足 / 3=枠切れで中断）。

**同じ指示書で2回失敗したら、3回目を投げる前に指示書を書き直す。**
だいたい原因はAntigravity側ではなく、指示書の完了条件が曖昧なこと。

## 無料枠の扱い

Antigravityの無料枠は週次補充で、具体的な数値は公開されていない（2026-09-18時点）。
2025年11月の提供開始以降、上限は何度も下方修正されている。
**枠がある前提で段取りを組まない。** 枠切れは通常運転の一部として扱い、
急ぐ作業はClaude Codeが自分で片付ける。
